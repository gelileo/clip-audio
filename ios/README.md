# ClipAudio — iOS app

Embeds CPython 3.14 + yt-dlp on-device. No backend, no companion daemon.
See `../prd.md` for the design and `../m0/M0-REPORT.md` for extraction feasibility.

## Build

```bash
./scripts/fetch_deps.sh        # Python.xcframework + vendored yt-dlp (gitignored)
cp Local.xcconfig.example Local.xcconfig   # set DEVELOPMENT_TEAM
xcodegen generate
open ClipAudio.xcodeproj
```

`project.yml` is the source of truth. **Never edit `.xcodeproj` by hand** — it is
gitignored and regenerated by `xcodegen`.

## How Python is embedded

`Python-Apple-support` ships an XCFramework holding only the interpreter binary;
an iOS XCFramework may not carry other content, so the standard library is
installed by a build phase instead:

- `install_python` (from `Support/Python.xcframework/build/utils.sh`) rsyncs the
  stdlib into `ClipAudio.app/python/lib/` at build time.
- Every stdlib `.so` extension module is repackaged into its own signed
  `.framework` under `Frameworks/`, leaving a `.fwork` pointer file behind.
  This is the PEP 730 mechanism — iOS cannot `dlopen` a bare `.so` from a
  bundle subdirectory. 67 modules are converted on a current build.
- A trim step then deletes CPython's own test suite and other unreachable
  packages. Without it the bundle is ~94MB; with it, ~50MB.

`ENABLE_USER_SCRIPT_SANDBOXING` must stay `NO` or the rsync is blocked.

## Layout

| Path | Role |
|---|---|
| `app/` | Our Python glue. Bundled as a folder reference. |
| `app_packages/` | Vendored pure-Python deps (yt-dlp, certifi). Gitignored. |
| `ClipAudio/shim/` | C bridge over the interpreter. JSON strings only — no Python objects cross it. |
| `ClipAudio/PythonRuntime.swift` | Serial queue + async wrapper. |
| `ClipAudio/SelfTest.swift` | Milestone gate checks; writes `Documents/m1gate.txt`. |
| `Support/` | Downloaded XCFramework. Gitignored. |

## Threading

`cpa_initialize` releases the GIL via `PyEval_SaveThread`; every later call
re-acquires with `PyGILState_Ensure`. That makes the bridge safe from a GCD
queue, which may migrate between OS threads — a plain
`Py_Initialize`-and-hold-the-GIL approach would not be.

## TLS

iOS ships no CA bundle where OpenSSL looks for one. `clipaudio_resolve`
points `SSL_CERT_FILE` at vendored `certifi` during boot. Without this every
network call fails certificate verification.

## Verifying a milestone gate

```bash
xcrun simctl install <sim-udid> build/dd/Build/Products/Debug-iphonesimulator/ClipAudio.app
xcrun simctl launch  <sim-udid> stream.clipaudio.app
cat "$(xcrun simctl get_app_container <sim-udid> stream.clipaudio.app data)/Documents/m1gate.txt"
```

The self-test runs before any UI work so the interpreter is measured cold.
A warm measurement reports `cold_measurement=false` and does not count.
